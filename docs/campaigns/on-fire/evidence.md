Applications use the existing Google-hosted `adrian@adrianwedd.com` mailbox. The link opens an editable draft with business, website, location, contact, optional concern and authority confirmation. Clicking does not submit, acknowledge receipt or award a place. The application text/address also work without JavaScript. A read-only mailbox query confirmed recent receipt to the published address on 25 October; Google MX records were observed. Adrian authorised the marked test on 25 October. The reply explicitly used `adrian@adrianwedd.com` and went to `adrianwedd@gmail.com`. Both messages have INBOX and SENT labels. This proves a same-account round trip and reply identity only; independent external-mailbox delivery and external spam handling remain unverified. Test reference: `ON-FIRE-MAIL-QA-20261025-747`. No ledger entry or award was created.

The canonical award ledger lives outside git at `~/.local/share/on-fire-campaign/ledger.json`. The default directory is private; records use mode 0600. One canonical host only. The lock covers read/order/count/write, duplicate awards are idempotent, all lifetime awards count towards ten, and the tool never requests a website or sends mail. Eligibility and business identity are human decisions. All earlier mailbox enquiries must be reviewed before awards; the tool cannot order messages it has not received. A static page cannot close itself on an administrative award: after the tenth, or an explicit early `close`, the ledger immediately refuses new intake and awards. Publish `closed: true` from the shared state file promptly. The first `closed_at` starts retention and is preserved by repeated closure; existing awards can still be delivered. Incoming mail while that release is pending must receive an honest full-offer reply.

[Operator guide](operator-guide.md) gives the ten operational steps, passive assessment scope, explicit intrusive-testing boundary, serious-compromise escalation, privacy/retention procedure and acknowledgement/award/decline/delivery templates. [Report template](report-template.md) is for a short plain-English report the owner can forward. Private copies of both were installed under `~/.local/share/on-fire-campaign/` with mode 0600. Filled reports/evidence belong there, never in this public repository. [Community announcements and source comment](launch-drafts.md) are prepared and unpublished.

Incremental recurring cost: **A$0 in new services**. Existing static hosting, email and protected device backups remain. No new database, CRM, cloud job, marketing integration or AI processing. No customer information was collected or sent during preparation. Existing unrelated media/artwork remains untouched; three unpublished Undertow commits remain preserved on local `main` and are excluded from this PR.
